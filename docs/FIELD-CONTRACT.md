# 字段契约

本文定义字段标签和导入规则, 是字段级契约的唯一来源.

- 数据库表结构: `src/main/resources/db/migration` 下的 Flyway 迁移
- 字段清单: `docs/field-dictionary.csv`

范围: 考勤批次, 考勤明细, 处罚明细. 其他表按同一规范增量补充.

本文只定义字段语义和标签, 不决定存储形态. 当前实现使用 `data_json`, 是否继续使用或改为拆列尚未决策; 标签和字段清单不受影响. CSV 的 `entity/key` 只反映当前落点.

快照用 `rule=快照` + `freeze=Y`, 不设独立标签.

## 1. 主标签 (7)

| Code | 中文 | 判定问题 | 谁说了算 | 导入行为 |
|---|---|---|---|---|
| K | 键/引用 | 用来匹配或关联别的记录吗 | 系统要求必须对上 | 可导入, 必须唯一或必须存在 |
| S | 状态 | 是状态机里的值吗 | 流程 | 禁止导入 |
| C | 派生 | 系统能按公式或查表算出来吗 | 系统 | 不作为权威, 只校验或忽略 |
| M | 度量 | 是带单位的数值业务量吗 | 源数据 | 可导入, 校验数值和精度 |
| D | 分类 | 是枚举, 分类或时间维度吗 | 源数据 | 可导入, 校验取值范围 |
| T | 透传 | 是自由文本或非结构化内容吗 | 源数据 | 可导入, 原样存取 |
| A | 审计 | 是系统生成的时间, 操作人或标记吗 | 系统 | 禁止导入 |

## 2. 五类辅助列

| 类别 | 列 | 说明 |
|---|---|---|
| 类型 | `type` | `string / integer / decimal / date / datetime / boolean / enum` |
| 口径 | `measure` | 单位, 精度, 长度或取值 |
| 约束 | `required` | 必填. 唯一和存在性写在 `rule` |
| 来源 | `source`, `scene` | 来源和场景 (通用/新增/修改) |
| 生命周期 | `importable`, `freeze` | 是否从文件采信, 写入后是否冻结 |

约定:

- `number` 改叫 `integer`, 指整数.
- 天, 小时, 次, 点用 `decimal`, 统一 6 位.
- 如果字段存在 `data_json`, `decimal` 存字符串, 避免浮点误差. 拆列时用 `DECIMAL`.
- 工号和编号是 `string`, 保留前导零, 不做运算.

## 3. 判定顺序

逐条问, 命中即停:

```text
1. 系统生成的元数据?        -> A
2. 标识, 外键, 匹配键?      -> K
3. 状态机值?                -> S
4. 系统按公式或查表产生?    -> C
5. 带单位的数值?            -> M
6. 枚举, 分类, 时间维度?    -> D
7. 其余自由文本?            -> T
```

跨场景拆行, 不双标签:

```text
处罚编号 @新增 -> C
处罚编号 @修改 -> K
```

## 4. 硬规则

1. 一个字段在一个场景下只有一个主标签.
2. 标 `C` 必须写清楚公式或查表来源. 没有确定规则的不许标 `C`.
3. 快照用 `rule=快照` + `freeze=Y`, 不新增标签.
4. `S` 和 `A` 一律 `importable=N`.
5. `K` 的唯一性和存在性写在 `rule`, 不写进标签.
6. `type` 只描述存储和解析, 不参与主标签判定.
7. `key` 用稳定英文 `snake_case`, 中文名只做展示.
8. 字段字典是唯一来源. 改字段必须同时改本文, 迁移和测试.

## 5. 字段字典 (当前实现映射)

以下是当前实现的字段映射, 不是存储决策. `docs/field-dictionary.csv` 列:

| 列 | 说明 |
|---|---|
| `entity` | 表或 payload |
| `key` | 建议英文 key |
| `current_key` | 当前存储 key (中文) |
| `label` | 中文名 |
| `tag` | `K/S/C/M/D/T/A` |
| `type` | 字段类型 |
| `measure` | 单位, 精度, 长度或取值 |
| `required` | `Y/N` |
| `source` | 数据来源 |
| `scene` | 通用/新增/修改 |
| `importable` | `Y/N` |
| `freeze` | `Y/N` |
| `rule` | 唯一, 存在, 公式或映射 |

关键结论:

- `福利假天数合计-FL` 和 `D0` 是 `M`, 不是 `C`. 需求没有公式.
- 处罚编号: `@新增=C`, `@修改=K`.
- 部门是 `C`, 按工号查用户, 忽略文件值, 查完冻结.
- `员工本人签字确认` 是 `C`, 不落库, 导出按 `status` 映射.
- 当前实现的 `data_json` 用中文 key; 若改为拆列, 以 CSV 的 `key` 为准.

## 6. 维护

- 新增字段先登记 CSV, 再改迁移, 实体, DTO, 模板和测试.
- 改字段同时更新本文、迁移和测试.
- 不修改已应用的 Flyway 迁移.
- 导入测试覆盖必填, 格式, 精度和重复. 处罚覆盖 `C @新增` 和 `K @修改`.
