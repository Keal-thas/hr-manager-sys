# 需求概要

**目的**: 考勤线上化 (员工本人电子签核, 取代纸质) 加入职资料线上推送 (定向下发, 签收有记录).
系统是凭证载体, 不做考勤计算, 指标由业务在 Excel 里算好导入.

**范围**: PC 端加企微. 企微本期只做消息推送, 见 [ADR-011](DECISIONS.md).

## 关键需求

模型见 [DATA-SCOPE.md](DATA-SCOPE.md).

| 领域 | 需求 | 要求 | 状态 |
|---|---|---|---|
| 考勤处罚 | K1 签收承诺加手写签名 | 员工先勾选同意, 再手写签名, 才算已确认 | 已做 |
| | K2 签字过程可回溯 | 留下签字过程的证据, 不只是一张签名图; 记什么未定 | 未做 |
| | K3 指标只展示不计算 | 30 多项指标和处罚点数由业务导入, 系统原样呈现 | 已做 |
| | K4 最新期和历史期分开 | 最新期可覆盖, 提醒; 历史期只增量和线下补签 | 已做 |
| | K5 处罚跟着考勤走 | 单独清单, 新增和修改两种导入, 员工签字时能看到 | 已做 |
| | K6 催办有精确对象 | 生成, 调整, 异常三类消息, 各发给不同的人 | 已做, 文案待确认 |
| 通知确认 | K7 入职资料下发加签收 | 定向下发, 并留下签收凭证 | 未做, 只有已读 |

核心是 K1, K2, K3.

## 其余

登录, 权限, 文案, 兼容性, 部门/角色/用户维护, 查询下载, 未读角标, 按常规实现.
量: 导入 5000 条, 通知 5000 人, 上传 180 秒内.
