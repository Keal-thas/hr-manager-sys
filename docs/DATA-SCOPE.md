# 数据模型说明: 考勤与通知

本文只描述业务数据模型和数据管理规则, 不展开技术字段.

字段级定义见 `docs/FIELD-CONTRACT.md`.

## 1. 考勤数据

### 1.1 数据模型

| 模型 | 一句话 |
|---|---|
| 考勤批次 | 一个年月一份考勤, 管上传方式, 是否最新和汇总人数. |
| 考勤记录 | 一个员工一个月的考勤结果, 管考勤字段, 状态和签字. |
| 处罚明细 | 挂在考勤记录下的一条处罚, 管编号, 等级, 原因和绩效点数. |
| 签字证据 | 员工怎么确认考勤: 在线签名, 签字过程回溯, 线下图片或 PDF. |

关系:

```text
考勤批次 -> 考勤记录 -> 处罚明细
                    -> 签字证据
```

### 1.2 数据管理

考勤批次:

- 年和月唯一, 不能晚于当前年月.
- 最新批次指年月最大的那一期, 不是最近上传的那一期.
- 只有最新批次支持覆盖上传, 修改上传, 考勤提醒和异常提醒.
- 非最新批次只支持增量上传和线下签字上传.
- 非最新批次的增量上传保存数据, 但不发企微消息.

考勤记录:

- 同一批次内一个工号只有一条记录.
- 状态为未阅读, 已阅读, 已确认.
- 员工打开明细后变为已阅读, 完成签字后变为已确认.
- 管理员线下签字上传后, 也变为已确认.
- 姓名和部门是导入时的快照, 后续部门调整不影响历史考勤.
- 用户注销后, 历史考勤和签字仍然保留.

处罚明细:

- 一个员工在一个批次里可以有多条处罚.
- 新增时系统生成编号, 编号规则为工号加月份加流水.
- 修改时按编号匹配已有处罚.
- 处罚中的工号必须存在于该批次的考勤记录.
- 处罚属于考勤凭证的一部分, 不随用户注销删除.

签字证据:

- 在线签名记录签名图片和签字时间.
- 签字过程回溯记录整个签字过程, 用于审计.
- 线下签字记录管理员上传的图片或 PDF.
- 一条考勤记录最终保留一份有效签字证据.
- 当前在线签名和线下签字都存入签名图片字段, 线下签字以 base64 data URL 保存.

覆盖和增量:

- 覆盖上传会重建该批次的考勤记录.
- 增量上传只新增或修改涉及的员工记录.
- 覆盖或增量后, 已确认状态和签名是否保留, 需要业务确认.

## 2. 通知数据

### 2.1 数据模型

| 模型 | 一句话 |
|---|---|
| 通知 | 管理员发布的一条通知, 管标题, 正文和发送范围. |
| 发送对象 | 通知发给谁: 全员, 部门或指定员工. |
| 用户消息 | 每个接收人收到的一条消息, 管已读未读. |
| 通知模板 | 可复用的通知标题和正文. |
| 企微投递日志 | 企微实际发送结果: 成功, 失败或跳过. |
| 通知附件 | 通知带的文件, 用于入职资料场景, 需求还没细化. |

关系:

```text
通知模板 -> 通知 -> 发送对象
                -> 用户消息 -> 企微投递日志
                -> 通知附件
```

### 2.2 数据管理

通知:

- 发送范围支持全员, 部门或指定员工.
- 指定员工支持搜索和清单导入, 同一通知内不能重复.
- 部门发送是否包含下级部门, 需要业务确认.
- 通知发布后生成接收人的用户消息.
- 发送对象在发送时固化, 后续部门或人员调整不影响历史通知.

用户消息:

- 每个接收人一条消息, 标题和内容保存发送时的快照.
- 进入详情页即视为已阅读, 已阅按钮不影响状态.
- 未读消息加粗显示, 并计入未读角标.
- 消息和阅读记录作为签收凭证保留.

通知模板:

- 支持新增, 修改, 注销和恢复.
- 注销后的模板不可用于新通知.
- 模板复用标题和正文, 不承载签收状态.

企微投递:

- 每条消息记录成功, 失败或跳过.
- 失败记录错误码和错误信息, 便于排查和重试.
- 企微发送失败不影响站内消息.

通知附件:

- 用于入职资料等文件下发场景.
- 需求只提到资料推送, 没有定义附件字段和阅读记录, 需要确认.

## 3. 两个域的关系

- 考勤提醒和通知都进入同一个用户消息收件箱, 用类型区分.
- 两个域共用企微投递日志.
- 未读角标由考勤未读数和消息未读数共同决定.

## 4. 待业务确认

- 覆盖或增量上传后, 已确认状态和签名是否保留.
- 签字过程回溯保存到什么颗粒度.
- 线下签字当前以 base64 存入签名图片字段; 生产是否改对象存储待定.
- 部门发送是否包含下级部门.
- 通知正文使用什么富文本格式.
- 入职资料是否需要附件和下载记录.
