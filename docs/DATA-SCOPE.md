# 领域模型

需求见 [REQUIREMENTS.md](REQUIREMENTS.md), 字段见 [FIELD-CONTRACT.md](FIELD-CONTRACT.md).

## 考勤处罚

```text
批次 -> 明细 -> 签字证据
批次 -> 处罚   (按工号对应明细)
```

| 概念 | 落地 |
|---|---|
| 批次 | 表 `attendance_batch` |
| 明细 | 表 `attendance_record` |
| 处罚 | 表 `attendance_penalty` |
| 签字证据 | 内嵌在明细里 |
| 签字过程 | **不存在** |

## 通知确认

```text
通知 -> 用户消息   (每人一条, 已读即确认)
```

| 概念 | 落地 |
|---|---|
| 通知 | 表 `message_notice` |
| 用户消息 | 表 `sys_message`, 考勤催办也写这里 |
| 发送对象 | 内嵌: 条件在通知里, 接收人就是用户消息 |
| 附件, 签收 | **不存在** |

## 要点

- 支撑: 员工, 部门, 角色 (明细按工号对应员工); 企微 (每条用户消息异步推送).
- 确认强度不同: 考勤是签字, 通知只是已读.
- **覆盖上传删光该批次的明细和处罚, 已确认的签名随之丢失.**
- **增量上传改了已确认的明细, 状态和旧签名不变, 签名对应的是旧数据.**
- 表之间没有物理外键.
