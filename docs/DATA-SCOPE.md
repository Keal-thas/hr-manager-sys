# 领域模型

需求见 [REQUIREMENTS.md](REQUIREMENTS.md), 字段见 [FIELD-CONTRACT.md](FIELD-CONTRACT.md).

本文只讲两个关键领域: **考勤处罚**和**通知确认**. 员工, 部门, 角色是支撑, 不展开. 两个领域在"用户消息"处交汇.

## 1. 考勤处罚

### 概念和关系

```text
批次 1-N 明细 1-1 签字证据
批次 1-N 处罚        (按工号对应明细)
明细 N-1 员工        (按工号)
```

| 概念 | 是什么 | 关键约束 | 落地 |
|---|---|---|---|
| 批次 | 一个年月一份考勤 | 年月唯一, 不晚于当前年月. 最新期是年月最大的, 不是最近上传的 | 表 `attendance_batch`, 最新期是存下来的标记 |
| 明细 | 一人一月的考勤结果 | 批次内工号唯一; 工号必须已存在, 姓名必须与员工一致; 指标由 Excel 导入, 不计算; 姓名和部门是导入时的快照, 部门取系统值, 文件值忽略 | 表 `attendance_record`, 30 多项指标存成一个 JSON |
| 处罚 | 一人一月可多条 | 批次内编号唯一 (工号加两位月份加三位流水); 导入分新增和修改; 工号必须已在当月明细里 | 表 `attendance_penalty`, 内容存成 JSON |
| 签字证据 | 员工确认的凭证 | 一条明细一份. 在线是手写签名加签名时间加同意标记; 线下是图片或 PDF, 不超过 10MB | **内嵌**在明细的三列里, 签名按 base64 存库 |
| 签字过程 | 回溯 | | **不存在** |

### 状态

```text
UNREAD --员工打开明细--> READ --员工签名 (必须同意)--> CONFIRMED
未确认 --管理员补签 (仅历史期)--> CONFIRMED
```

上传时, 未确认的明细一律重置为 UNREAD.

### 上传

| 方式 | 前提 | 明细 | 处罚 | 已确认的签名 | 发消息 |
|---|---|---|---|---|---|
| 新增 | 该年月不存在 | 全部新建, UNREAD | | | 清单全员, "已生成" |
| 覆盖 | 仅最新期 | **全删后重建**, UNREAD | **全删** | **清空** | 清单全员, "已调整" |
| 增量 | 该年月已存在 | 按工号新增或更新 | 保留 | **保留旧签名, 但数据已变** | 仅最新期: 新增的"已生成", 被改的"已调整"; 历史期不发 |

### 催办

只限最新期. 考勤提醒发给状态非已确认的人; 异常提醒发给状态为未阅读且有处罚的人.

### 保持不变的

- 部门改名, 删除, 注销, 都不影响历史明细.
- 员工注销后, 明细, 签字, 处罚都保留.
- 最新期必须员工在线签字; 线下补签只对历史期开放.

## 2. 通知确认

### 概念和关系

```text
通知 1-N 用户消息       (用户消息记下来源通知)
用户消息 N-1 员工
用户消息 1-0..1 企微投递  (按用户对应, 无外键)
通知模板                  (独立, 发布时可顺手存一份)
```

| 概念 | 是什么 | 关键约束 | 落地 |
|---|---|---|---|
| 通知 | 管理员发布的一条 | 标题不超过 100 字, 正文不超过 10000 字 (需求要富文本); 发送范围三选一; 接收人为空则拒绝 | 表 `message_notice` |
| 发送对象 | 发给谁 | 全员取所有有效员工; 部门取所选部门**及其下级**的有效员工; 指定取所选的有效员工. 发布时就展开成接收人 | **内嵌**: 范围条件存在通知里, 接收人落成用户消息 |
| 用户消息 | 每个接收人一条 | 标题和正文是发送时的快照; 记下来源类型和来源 ID; 有已读标记 | 表 `sys_message` |
| 企微投递 | 推送结果 | 异步; 成功, 失败 (带错误码), 跳过 (没有企微 ID 且未启用工号回退); 失败不影响站内消息 | 表 `wecom_message_log` |
| 通知模板 | 可复用的标题和正文 | 新增, 修改, 注销, 恢复 | 表 `notice_template` |
| 附件, 签收 | 入职资料文件及签收 | | **不存在** |

### 确认

- 这里的"确认"是已读: 员工打开详情时, 前端调用已读接口; 未读加粗, 计入角标; 也可以全部已读.
- 只有已读标记, **没有阅读时间, 没有签收**.
- 对比考勤: 考勤确认是签字, 强凭证; 通知确认只是已读, 弱凭证. 需求目的要入职资料"签收有凭证", 目前达不到.

### 交汇: 用户消息

用户消息是两个领域共用的收件箱, 靠类型区分来源:

| 类型 | 来源 | 记下的来源 ID |
|---|---|---|
| NOTICE | 通知发布 | 通知 |
| ATTENDANCE | 考勤上传 | 批次 |
| ATTENDANCE_REMIND | 考勤提醒 | 批次 |
| ATTENDANCE_ABNORMAL | 异常提醒 | 批次 |

每条用户消息写入后, 若已启用企微, 就异步推送一次.

## 3. 缺口

- 考勤处罚: 没有签字过程记录; 没有阅读时间, 确认时间只有签名时间; 没有调整历史, 覆盖是物理删除; 确认接口不校验是否最新期.
- 通知确认: 没有附件, 没有签收, 没有阅读时间.

表之间没有物理外键, 关联全靠应用层.
