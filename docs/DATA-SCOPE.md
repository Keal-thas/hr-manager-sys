# 领域模型

按原需求整理, 不含实现. 需求见 [REQUIREMENTS.md](REQUIREMENTS.md), 字段见 [FIELD-CONTRACT.md](FIELD-CONTRACT.md).

只讲两个关键领域: **考勤处罚**和**通知确认**. 员工, 部门, 角色是支撑, 不展开.

## 1. 考勤处罚

### 对象与关系

```text
考勤 (按年月) 1-N 考勤明细 (员工 x 月) 1-1 签字确认
考勤 (按年月) 1-N 处罚明细 (员工 x 月, 可多条)
处罚明细 --工号--> 同一考勤里该员工的明细
```

| 对象 | 需求里是什么 |
|---|---|
| 考勤 | 一个年月一份, 有"最新月份". 汇总四个人数: 上传, 已确认, 阅读未确认, 未阅读. 三种上传: 新增, 覆盖, 增量或修改 |
| 考勤明细 | 一人一月. 30 多项指标由 Excel 导入; 状态为未阅读, 已阅读, 已确认; 带说明 |
| 处罚明细 | 一人一月可多条. 通过"考勤异常清单"导入, 分新增和修改. 新增时系统生成编号: 工号加两位月份加三位流水 |
| 签字确认 | 勾选"本人承诺已认真阅读, 明白并认可其法律含义", 再手写签名, 同时开启签字过程回溯. 线下方式是管理员上传图片或 PDF |

### 唯一标识

| 对象 | 唯一标识 | 怎么用 |
|---|---|---|
| 考勤 | 年加月 | 覆盖和增量靠它找到要改的那一份; "最新"按年月比, 不看上传时间 |
| 考勤明细 | 年月加工号 | 增量时按工号匹配: 已有则覆盖该员工, 没有则新增 |
| 处罚明细 | 年月加编号 | 新增时系统生成, 修改时按编号匹配 |
| 员工 | 工号 | 明细和处罚都靠工号对应员工 |

编号是工号加两位月份加三位流水, **不含年份**, 只在同一年月内唯一, 匹配必须限定在选定的年月里.

### 状态

```text
未阅读 --员工打开明细--> 已阅读 --员工勾选并签名--> 已确认
未确认 --管理员上传线下签字--> 已确认
```

### 三种上传

| 方式 | 前提 | 效果 | 通知员工 |
|---|---|---|---|
| 新增 | 年月不晚于当前 | 新建一份考勤 | 清单全员: 已生成 |
| 覆盖 | 仅最新月份 | 全量覆盖重传 | 清单全员: 已调整 |
| 增量或修改 | 仅最新月份 | 工号不存在则新增, 已存在则覆盖该员工 | 新增的: 已生成; 修改的: 已调整 |
| 增量 | 非最新月份 | 同上 | **不通知** |

### 员工看到什么

- PC 端只看当月, 当月没上传则为空. 企微只看最新一期.
- 未确认进确认页, 已确认进详情页. 处罚明细随考勤明细一起展示.

### 催办与补签

- 催办只限最新月份. 考勤提醒发给未阅读和阅读未确认的人; 异常提醒发给未阅读且有处罚的人.
- 线下补签只限非最新月份, 且仍有人未确认. 管理员只能在未阅读和已阅读的人里补, 上传后变已确认.
- 管理员可以查看员工的签名图片.

### 导入校验

- 工号必须是数字, 批次内不重复, 且必须有对应的员工; 姓名必须与员工一致.
- 部门不看文件, 按员工所属部门保存.
- 数值指标最多 6 位小数, 必填; 出错整批取消, 提示具体工号和字段.
- 处罚的工号必须在同一考勤里; 修改时按编号匹配, 匹配不到则整批取消.
- "员工本人签字确认"不导入, 由员工签字后赋值; 导出时按状态给值.

### 保持不变的

- 部门改名, 删除, 注销, 都不影响已导入的明细.
- 员工注销后, 考勤记录仍保留.

## 2. 通知确认

### 对象与关系

```text
通知模板 --选用或存为--> 通知 --展开--> 接收人 1-1 通知消息 (已读或未读)
通知消息 --提醒--> 企微消息
```

| 对象 | 需求里是什么 |
|---|---|
| 通知 | 管理员发布. 标题 (100 字), 正文 (10000 字, 富文本), 发送范围, 是否同时存为模板 |
| 发送对象 | 全员: 所有有效员工. 部门: 勾选部门下所有归属的有效员工. 指定: 搜索或导入工号清单, 同一通知内不重复, 两种方式可混用 |
| 通知消息 | 员工看到的一条: 标题, 发布日期, 状态为未阅读或已阅读. 可按标题模糊查, 按状态筛 |
| 通知模板 | 新增, 修改, 注销, 恢复. 记录创建人, 最新修改人及时间 |
| 企微消息 | 考勤和通知都会推一条提醒到企微; 考勤的有生成, 调整, 异常三类 |
| 附件, 签收 | 目的里提到的入职资料, 需求**没有定义** |

### 确认

- 这里的"确认"是已读: 员工进入详情就算已读, "已阅"按钮不影响状态. 未读加粗.
- 没有签收. 对比考勤: 考勤确认是签字, 强凭证; 通知确认只是已读, 弱凭证.

### 交汇

两个领域在**企微**处交汇: 考勤的三类提醒和通知的提醒都走企微. 员工自助上有未读角标, 总数是未读考勤加未读通知.

需求里考勤提醒只发企微; "消息通知"页只放管理员发布的通知.

## 3. 需求里没定的

1. 覆盖或增量后, 已确认的状态和签名是否保留.
2. 签字过程回溯记什么, 保留多久.
3. 入职资料要不要附件, 签收是已读还是单独确认.
4. FL 和 D0 的计算方式 (名称像公式, 冲抵规则没给); 缩略语没有定义.
5. 工号能否修改: 用户修改页可改, 个人中心写"联系管理员".
6. 通知是否有重要程度和发布部门: 企微消息示例里出现了, 规则里没有.
7. 部门发送是否含下级: 需求只写"部门下所有归属的有效用户".
8. 员工可见范围: PC 看当月, 企微看最新期, 月初两者不同.
9. 考勤消息文案有两套.
